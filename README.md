# 网页测距仪 · Web Ruler

用参照物标定,在**照片**或**实时摄像头画面**上测量真实长度。纯前端、无需安装、不联网、不上传任何照片。

> 一句话原理:先告诉程序「画面里这个东西有多长」,它就能推算出画面里别的东西有多长。
> 这个东西叫**参照物**。参照物越标准、在画面里越大,结果越准。

---

## 它能做什么

| 模式 | 说明 | 适合 |
|---|---|---|
| **照片** | 上传一张照片,点选参照物,再点两点量长度 | 量已经拍好的照片里的东西 |
| **相机** | 打开摄像头实时测量 | 站在东西前面直接量 |
| **AR** | 真·三维平面检测,不需要参照物 | 只在支持的设备上出现(见下) |

**核心能力:矩形透视校正。** 如果参照物是矩形(银行卡、A4 纸)且能看到四个角,程序会解出单应矩阵把斜面还原成正视的毫米平面 —— 这能真正消除「斜着拍」带来的误差,比单纯的两点比例标定准得多。

---

## 怎么用(三步)

1. **选参照物** —— 右侧列表里选。银行卡、A4 纸是**国际标准尺寸**,最准。
2. **点参照物** —— 矩形参照物点四个角(左上 → 右上 → 右下 → 左下);线性参照物点两端。
3. **量长度** —— 在被测物上点两个点,长度立刻显示。点可以**拖动微调**,数字实时更新。

### 参照物怎么选

| 参照物 | 真实尺寸 | 说明 |
|---|---|---|
| 银行卡 / 身份证 | 85.6 × 53.98 mm | **推荐**。ISO/IEC 7810 标准,全球统一,随手就有 |
| A4 / A3 纸 | 297×210 / 420×297 mm | ISO 216 标准,面积大好点角 |
| 1 元硬币 | 直径约 25 mm | 适合小物体,注意流通磨损 |
| 烟盒 | 约 85 × 55 mm | ⚠️ **各国各品牌差异很大**,请先自己量一次 |
| 自定义(如「一拃」) | 你说了算 | 用尺子量一次存下来,以后复用 |

> ⚠️ 标记「约」的参照物是**常见值不是标准值**,建议先用尺子核对。程序里也标了 `approximate`,界面上会提示。

## 三步让结果更准

1. **让参照物占满画面。** 参照物在照片里的像素越多,误差越小。参照物只有 50 像素宽时误差约 4%,放大到 400 像素就降到 0.5% 左右。
2. **参照物和被测物放在同一平面上**(同一张桌面最好)。两者离相机远近差别大时会有系统偏差 —— 这是针孔成像的必然结果,不是 bug。
3. **能斜着拍就用矩形模式。** 只要能看到参照物四个角,透视校正会把「近大远小」还原掉。

程序会实时给出**精度估算**(绿/黄/红),并告诉你哪里可以改进。

## 已知限制(请务必先读)

- **量「立体的高度」不准。** 这是所有单张照片/单目测量的通病 —— 第二个点悬在空中,算法只能把它投射到平面上。**iPhone 自带的测距仪也有同样的问题。** 量平面上的距离是准的。
- **参照物必须和被测物共面。** 拍远景时拿手里的银行卡去标定近处的东西,一定不准。
- **精度估算给的是量级,不是保证值。** 网页端拿不到相机内参和镜头畸变参数,所以这是启发式估算,用来判断「这次能信到哪一位」。
- **「烟盒」「一拃」这类尺寸因人而异。** 请先用尺子核对。

## 关于 AR 模式(重要)

AR 模式需要浏览器支持 **WebXR**。现实情况是:

| 设备 | AR 可用? |
|---|---|
| 安卓 + Chrome + 装了 Google Play 服务(ARCore) | ✅ |
| 国产安卓(无谷歌服务) | ❌ |
| **iPhone / iPad 全部** | ❌ |
| 桌面浏览器 | ❌ |

**iPhone 的 Safari 至今不支持 WebXR**,Apple 尚未实现该功能([WebKit bug 208988](https://bugs.webkit.org/show_bug.cgi?id=208988) 仍开启,[caniuse 支持表](https://caniuse.com/webxr)显示 Safari on iOS 3.2~27.x 全部不支持)。所以 **iPhone 上不会出现「AR」标签页 —— 这不是 bug。**

安卓上也需要设备装有 ARCore(通过 Google Play 服务分发)。

**没有 AR 完全不影响使用**:相机 + 参照物标定是全平台都能用的主力方案,而且在「量桌面上东西」这个最常见的场景里,精度和 AR 相当甚至更好。

> AR 那部分代码(含 three.js,约 520 KB)是**动态加载**的 —— 不支持的设备一个字节都不会下载。

- **纯前端,无后端。** 没有服务器,没有数据库。
- **不联网。** 不含任何远程字体、CDN、统计脚本。构建产物里没有任何外部请求。

## 部署到 GitHub Pages(拿到一个链接)

### 方式一:GitHub Actions(推荐)

仓库里已经配好了 `.github/workflows/deploy.yml`。推送代码后:

1. 打开仓库 → **Settings** → 左侧 **Pages**
2. 在 **Source** 下选 **GitHub Actions**(不是 "Deploy from a branch")
3. 回到 **Actions** 标签页,等 "Deploy to GitHub Pages" 跑完
4. 链接是 `https://<你的用户名>.github.io/<仓库名>/`

之后每次推送到 `main`,网站会自动更新。

### 方式二:手动构建后上传

```bash
npm install
npm run build          # 产物在 dist/
```

把 `dist/` 里的内容传到任意静态托管即可。

### ⚠️ 必须是 HTTPS

浏览器只在**安全上下文**下允许调用摄像头。`https://` 和 `localhost` 算安全上下文,`http://` 的 IP 地址不行。

GitHub Pages 自带 HTTPS,所以部署上去就能直接用摄像头。如果你自己在局域网里测试,需要 `localhost` 或者自签证书。


## 技术要点

- **纯前端**,无框架。Vite 构建,原生 ES 模块。
- **几何核心**(`src/geometry.js`)是纯函数,无 DOM 依赖,有单元测试覆盖 —— 包括用已知投影矩阵反解验证透视校正的精度。
- **测量点位一律存「原图像素坐标」**,屏幕坐标只是渲染时的临时投影。所以缩放、旋转屏幕、改窗口大小都不会让测量点错位。
- **长度永远按需重算,不缓存。** 因为用户拖点后必须立刻更新,缓存会导致「线动了数字没动」。
- 主包仅 **35 KB**(gzip 14 KB),AR 部分单独分包(约 510 KB),只有支持的设备才下载。
- **两条主路径都有自动化验证**:照片模式和摄像头模式各有一个真实浏览器冒烟测试,在 CI 里每次推送都会跑,并断言测量数值正确。
